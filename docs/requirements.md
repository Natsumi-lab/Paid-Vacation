# 有給休暇管理アプリ 要件定義書

## 1. プロジェクト概要

従業員の有給休暇日数を管理するWebアプリケーション。
従業員が自ら有給休暇を申請し、管理者が承認/却下するワークフローを実現する。

### 対象規模
- 従業員数: 10人程度

---

## 2. ユーザーと権限

### 2.1 ユーザー種別

| 種別 | 説明 |
|------|------|
| 管理者 | 従業員の登録・編集、有給申請の承認/却下、全従業員の有給状況確認 |
| 従業員 | 自分の有給申請、自分の有給残日数・履歴確認 |

### 2.2 認証

- ログイン方法: 社員番号 + パスワード
- パスワードリセット機能: あり（メールによるリセット）

---

## 3. 機能要件

### 3.1 従業員向け機能

| 機能 | 説明 |
|------|------|
| ログイン/ログアウト | 社員番号とパスワードで認証 |
| パスワードリセット | メールでリセットリンクを送信 |
| 有給残日数確認 | 現在の有給残日数を表示 |
| 有給申請 | 取得希望日・種別（全休/午前半休/午後半休）・理由を入力して申請 |
| 申請履歴確認 | 自分の申請一覧と承認ステータスを確認 |
| 申請取消 | 申請中（未承認）の申請をキャンセル |

### 3.2 管理者向け機能

| 機能 | 説明 |
|------|------|
| 従業員管理 | 従業員の登録・編集・削除 |
| 有給申請一覧 | 全従業員の申請一覧を表示 |
| 承認/却下 | 申請中の有給を承認または却下（却下理由を入力可） |
| 有給残日数確認 | 全従業員の有給残日数一覧を表示 |
| 有給付与 | 手動での有給日数調整（必要に応じて） |

### 3.3 承認フロー

```
従業員が申請 → 申請中 → 管理者が確認 → 承認済み or 却下
```

| ステータス | 説明 |
|-----------|------|
| 申請中 | 従業員が申請、管理者の確認待ち |
| 承認済み | 管理者が承認、有給残日数から減算 |
| 却下 | 管理者が却下、残日数は変わらない |

---

## 4. 有給休暇ルール

### 4.1 付与ルール（日本の労働基準法準拠）

入社日を基準に、以下のタイミングで有給休暇を付与する。

| 勤続期間 | 付与日数 |
|---------|---------|
| 6ヶ月 | 10日 |
| 1年6ヶ月 | 11日 |
| 2年6ヶ月 | 12日 |
| 3年6ヶ月 | 14日 |
| 4年6ヶ月 | 16日 |
| 5年6ヶ月 | 18日 |
| 6年6ヶ月以上 | 20日 |

### 4.2 繰越ルール

- 未使用の有給休暇は翌年度に繰り越し可能
- 繰越上限: **最大20日**
- 有効期限: 付与日から2年間（労働基準法に準拠）

### 4.3 取得単位

| 種別 | 消化日数 |
|------|---------|
| 全休 | 1.0日 |
| 午前半休 | 0.5日 |
| 午後半休 | 0.5日 |

## 9. 非機能要件

### 9.1 セキュリティ

- パスワードはハッシュ化して保存（bcrypt）
- セッション管理による認証
- CSRF対策
- SQLインジェクション対策（ORMによるパラメータ化クエリ）

### 9.2 パフォーマンス

- ページ読み込み: 3秒以内
- API応答: 1秒以内

### 9.3 可用性

- Vercelの標準SLAに準拠

## 11. 用語定義

| 用語 | 定義 |
|------|------|
| 全休 | 1日分の有給休暇 |
| 半休 | 0.5日分の有給休暇（午前または午後） |
| 繰越 | 前年度の未使用有給を当年度に持ち越すこと |
| 付与 | 勤続期間に応じて有給日数を与えること |
